# Architecture rules
- Keep external firing orders admin-only; calculate totals in integer cents in both the shared calculator and generated database column. Standard tariffs are orientative: admins may set `custom_total_cents`, which then replaces the generated total everywhere it is displayed or summed.

- Group selection quotes and displayed price breakdowns by class month; use the existing authenticated quote RPC for each month to preserve incremental pricing.
- Keep selected class records across calendar navigation so payment includes precisely the visible selection summary, including selections in other months.
- Group income app payments by class month and collection state, preserving cash monthly totals without hiding outstanding added classes inside collected amounts; only cash payments support manual collection actions.
- Make-up credits belong to the calendar month (Europe/Madrid) of the ROOT cancelled class: `makeup_origin_month()` uses `makeups.origin_month` when set, else walks the make-up chain (cycle-safe, fail closed); manual courtesy credits store the grant month. Usable until the first instant of the next month (`makeup_deadline()`); an earlier expires_at only limits, never extends. Enforced in `book_makeup`/`admin_move_booking`; cancelling a make-up frees the same credit. Admin moves across months are blocked so tiers never carry between months.
- After any cancellation/removal of an adult drop-in, `recalc_month_pending_cash` re-prices only that month's pending cash rows and syncs the mirrored ledger; confirmed payments are never modified. Regression SQL lives in `supabase/tests/` and must roll back.
- Class "Bloquear horario" (status cancelled_by_admin) only closes the agenda and keeps bookings; a real studio cancellation goes through `admin_cancel_class` (status cancelled), which mirrors auto-cancel (credits by root month, void pending cash, ledger sync, notify) and is idempotent. Regression: `supabase/tests/admin_cancel_class.sql`.
