# Architecture rules
- Link independent accountless class attendees through `workshops.class_id`; count linked attendees in capacity helpers and admin rosters without attaching them to another student's booking, exposing names publicly, or creating payments.
- Keep external firing orders admin-only; calculate totals in integer cents in both the shared calculator and generated database column. Standard tariffs are orientative: admins may set `custom_total_cents`, which then replaces the generated total everywhere it is displayed or summed.

- Group selection quotes and displayed price breakdowns by `billingMonthKey`, retaining `billing_month` in quote inputs; use the authenticated quote RPC per billing month so exceptional dates share that month's incremental tier.
- Keep selected class records across calendar navigation so payment includes precisely the visible selection summary, including selections in other months.
- Group income app payments by class month and collection state, preserving cash monthly totals without hiding outstanding added classes inside collected amounts; only cash payments support manual collection actions.
- Make-up credits belong to the billing month of the ROOT cancelled class (`class_billing_month`, calendar month Europe/Madrid unless the class sets `billing_month`); a target class qualifies when its calendar or billing month equals that month: `makeup_origin_month()` uses `makeups.origin_month` when set, else walks the make-up chain (cycle-safe, fail closed); manual courtesy credits store the grant month. Usable until the first instant of the next month (`makeup_deadline()`); an earlier expires_at only limits, never extends. Enforced in `book_makeup`/`admin_move_booking`; cancelling a make-up frees the same credit. Admin moves across months are blocked so tiers never carry between months.
- After any cancellation/removal of an adult drop-in, `recalc_month_pending_cash` re-prices only that month's pending cash rows and syncs the mirrored ledger; confirmed payments are never modified. Regression SQL lives in `supabase/tests/` and must roll back.
- Class "Bloquear horario" (status cancelled_by_admin) only closes the agenda and keeps bookings; a real studio cancellation goes through `admin_cancel_class` (status cancelled), which mirrors auto-cancel (credits by root month, void pending cash, ledger sync, notify) and is idempotent. Regression: `supabase/tests/admin_cancel_class.sql`.
- A class may set `classes.billing_month` to count toward another month's adult tier; pricing SQL and frontend grouping use it (`billingMonthKey`), make-up credit months stay calendar-based.
- Share pure billing-month and priced-line grouping in `supabase/functions/_shared/class-billing.ts` across browser and checkout code to prevent month drift between runtimes.
- Future cash batches and Stripe receipts use separate ledger keys per billing month and retain actual payment dates; `record_drop_in_ledger` is server-only and ignores already recorded receipts so retries never rewrite settled history.
- Income views count pending payment methods as alternatives per booking, preferring collectible cash until settlement; retain all confirmed payments because completed charges must never be silently hidden.
- Credit creators store `origin_month`/`expires_at` from `class_billing_month`, so a class billed in another month is recovered within that month; `makeup_billing_month` stays the source for root-class cash repricing. Regression: `supabase/tests/makeup_follows_billing_month.sql`.
